# Kontrolna lista – OWASP ASVS 5.0.0 (odabrani zahtjevi) – MedTermin – naručivanje pregleda, varijanta V01

OWASP *Application Security Verification Standard* (ASVS) 5.0.0 je standard zahtjeva za provjeru sigurnosti web aplikacija (razine L1–L3). Za projekt MedTermin V01 odabran je reprezentativni podskup od 25 ključnih zahtjeva. Za svaki zahtjev analizirano je stanje aplikacije **prije** i **poslije** primjene sigurnosnih popravaka definiranih planom ispravljanja.

Oznake statusa:
- **Da** – zahtjev je u potpunosti ispunjen
- **Djelomično** – zahtjev je djelomično implementiran ili postoje rubni slučajevi
- **Ne** – zahtjev nije ispunjen (prisutna je ranjivost ili nedostatak)
- **N/P** – nije primjenjivo u danom kontekstu (uz detaljno obrazloženje)

| ID | Razina | Zahtjev (skraćeno) | Prije | Poslije | Dokaz |

| **1.2.1** | L1 | Izlazno kodiranje (HTTP odgovor, HTML, XML) primjereno je kontekstu u koji se podatak umeće. | **Djelomično** | **Da** | **Prije:** `IspisController.java` ispravno koristi `HtmlUtils.htmlEscape`, ali u `PrijavaController.java` poruke o greškama i parametri interpoliraju se ručno, a u `NalazController.java` sirovi tekst iznimke vraća se u polju napomene. **Poslije:** Svi korisnički ulazi i poruke se strogo kontekstualno kodiraju (HTML entity encoding), a greške se vraćaju kroz strukturirani generički JSON format bez interpolacije sirovog korisničkog unosa. |
| **1.2.4** | L1 | Upiti prema bazi koriste parametrizirane upite, ORM ili su na drugi način zaštićeni od SQL injectiona. | **Ne** | **Da** | **Prije:** `LijecnikController.popis` izravno spaja parametre `sort` i `smjer` u SQL naredbu konkatenacijom (`ORDER BY " + sort + " " + smjer`), što omogućuje SQL injekciju (N-09 / M11; Semgrep pravila `tainted-sql-string` i `spring-sqli`, FindSecBugs `SQL_INJECTION_SPRING_JDBC`). **Poslije:** Uvedena je stroga allowlista dopuštenih stupaca (`ime`, `prezime`, `specijalizacija`, `ordinacija`) i provjera smjera (`ASC`/`DESC`). Ostali upiti u `JdbcPomoc` koriste parametrizirani `JdbcTemplate` s `?` veznim parametrima. |
| **1.5.1** | L1 | XML parseri su konfigurirani restriktivno; nesigurne mogućnosti poput razrješavanja vanjskih entiteta su isključene. | **Da** | **Da** | **Prije:** `UvozTermina.java` u metodi `tvornica()` eksplicitno postavlja sigurnosna svojstva: `disallow-doctype-decl = true`, `external-general-entities = false`, `external-parameter-entities = false`, `XIncludeAware = false`. SpotBugs nalaz `XXE_DOCUMENT` (T01) je lažno pozitivan. **Poslije:** Sigurnosna konfiguracija je sačuvana i potvrđena regresijskim testom `UvozTerminaFunkcionalniTest`. |
| **1.5.2** | L2 | Deserijalizacija nepouzdanih podataka je sigurna (npr. dopušteni popis tipova objekata). | **Ne** | **Da** | **Prije:** `PostavkeController.spremi` koristi `new Yaml().load(...)` nad korisničkim unosom sa zadanom SnakeYAML 1.33 konfiguracijom koja dopušta instanciranje proizvoljnih tipova (CVE-2022-1471 / N-10; prijavili OSV, Trivy i Dependency-Check). **Poslije:** Uveden je `SafeConstructor` (`new Yaml(new SafeConstructor(new LoaderOptions()))`) koji dopušta samo osnovne tipove podataka (mape, stringove, brojeve), čime je onemogućeno instanciranje opasnih Java klasa. |
| **2.3.3** | L2 | Poslovna operacija uspije u cijelosti ili se vrati u prethodno ispravno stanje (transakcije). | **Da** | **Da** | **Prije:** `RezervacijaService.obrisi` i `TerminController.uvezi` koriste anotaciju `@Transactional`. U `RezervacijaService.kreiraj` u slučaju neuspjeha vanjskog BIS poziva postoji kompenzacijska akcija koja dekrementira broj zauzetih mjesta (`UPDATE termini SET zauzeto = zauzeto - 1`). **Poslije:** Sve višekoračne bazične operacije zaštićene su transakcijskim upravljanjem i kompenzacijskim mehanizmima. |
| **2.3.4** | L2 | Resursi ograničene količine zaštićeni su zaključavanjem na razini poslovne logike (npr. dvostruka rezervacija). | **Da** | **Da** | **Prije:** `RezervacijaService.kreiraj` koristi atomski SQL uvjetni update: `UPDATE termini SET zauzeto = zauzeto + 1 WHERE id = ? AND zauzeto < kapacitet`. Ako je ažurirano 0 redaka, baca se `HttpStatus.CONFLICT`, što sprječava stanje utrke (race condition) i prebukiravanje termina. **Poslije:** Mehanizam je zadržan i verificiran testom konkurentnih rezervacija. |
| **3.4.1** | L1 | Odgovori sadrže zaglavlje `Strict-Transport-Security` (HSTS). | **N/P** | **N/P** | **Prije i poslije (Lokalno okruženje):** Aplikacija se lokalno razvija i pokreće isključivo putem HTTP protokola (`http://localhost:8080`), stoga slanje HSTS zaglavlja lokalno nije primjenjivo jer preglednici ignoriraju HSTS preko čistog HTTP-a. **Produkcijsko rješenje:** U produkcijskom okruženju HSTS zaglavlje (`max-age=31536000; includeSubDomains; preload`) postavlja se na razini TLS terminacijskog reverse proxyja (Nginx / Cloudflare / Ingress) ili kroz Spring Security konfiguraciju (`headers().httpStrictTransportSecurity()`). |
| **3.4.2** | L1 | `Access-Control-Allow-Origin` je fiksna vrijednost ili se zaglavlje `Origin` provjerava prema popisu dopuštenih. | **Ne** | **Da** | **Prije:** `CorsFilter.dopusten` prihvaća bilo koji origin koji započinje s `http://` ili `https://` i postavlja `Access-Control-Allow-Credentials: true` (N-07 / M07), što omogućuje bilo kojoj zlonamjernoj web domeni slanje zahtjeva s vjerodajnicama žrtve. **Poslije:** Provjera se izvodi isključivo prema konfiguriranoj allowlisti (`AppProperties.allowedOrigins`, zadano `http://localhost:5173`). Nepoznati izvori se odbijaju bez slanja CORS zaglavlja. |
| **3.4.3** | L2 | Odgovori sadrže zaglavlje `Content-Security-Policy`. | **Djelomično** | **Da** | **Prije:** Samo `IspisController.potvrda` eksplicitno postavlja zaglavlje `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`. Odgovori kontrolera `PrijavaController` nemaju CSP zaglavlje. **Poslije:** Globalni filter ili Spring Security postavlja restriktivno CSP zaglavlje na sve HTML stranice aplikacije. |
| **3.7.2** | L2 | Aplikacija automatski preusmjerava samo na odredišta s popisa dopuštenih (ili upozorava korisnika). | **Ne** | **Da** | **Prije:** `PrijavaController.odrediste` slijepo vraća nepouzdani parametar `returnUrl` u zaglavlje `Location` (`HttpStatus.FOUND`), što predstavlja otvoreno preusmjeravanje (Open Redirect, N-08 / M08). **Poslije:** Implementirana je provjera: dopuštene su isključivo relativne lokalne putanje koje započinju s `/`, a odbijaju se apsolutni URL-ovi, sheme protokola i protokol-relativne putanje (`//host`). U slučaju nevaljanog unosa vraća se zadana putanja `/`. |
| **5.3.2** | L1 | Pri radu s putanjama datoteka koriste se interno generirani podaci; korisnička imena datoteka se strogo provjeravaju. | **Ne** | **Da** | **Prije:** `NalazController.preuzmi` koristi korisnički zadan parametar `datoteka` i samo provjerava `datoteka.contains(korisnik.username())`, nakon čega poziva `pohrana.dokumenti().resolve(datoteka)`. To omogućuje Path Traversal (N-02 / M02) i preuzimanje tuđih ili sistemskih datoteka pomoću `..`. **Poslije:** Datoteke se identificiraju preko ID-a nalaza u bazi podataka; putanja se kanonizira (`normalize()`, `toRealPath()`) i strogo provjerava ostaje li unutar korijenskog direktorija pohrane (`./data/dokumenti`). |
| **6.2.1** | L1 | Lozinke koje postavlja korisnik imaju najmanje 8 znakova. | **Da** | **Da** | **Prije:** `KorisnikService.provjeriLozinku` provjerava `MIN_DULJINA_LOZINKE = 8` pri registraciji, promjeni i resetu lozinke te u suprotnom baca `ApiException.neispravno`. **Poslije:** Pravilo je u potpunosti zadržano i potvrđeno testom `AutentikacijaFunkcionalniTest`. |
| **6.4.3** | L2 | Postupak obnove zaboravljene lozinke je siguran. | **Ne** | **Da** | **Prije:** Postupak je višestruko ranjiv: token se računa deterministički kao MD5 korisničkog imena i trenutnog datuma (N-03 / M03), a pri postavljanju nove lozinke ne provjerava se istek niti se token označava iskorištenim (N-04 / M04). **Poslije:** Token se generira pomoću `SecureRandom` s 256 bita entropije, u bazi se pohranjuje njegov SHA-256 sažetak, uveden je rok valjanosti od 15 minuta te se token atomski poništava nakon prve uspješne uporabe. |
| **8.2.1** | L1 | Pristup funkcijama ograničen je na korisnike s izričitim ovlastima. | **Da** | **Da** | **Prije:** `AuthFilter` zahtijeva valjanu autentikaciju za sve rute osim javnih (`/`, `/prijava`, `/reset`, `/api/health`, `/api/auth/*`), a `TerminController.uvezi` izričito provjerava posjeduje li korisnik ulogu `LIJECNIK` ili `ADMIN` (`korisnik.imaUlogu("LIJECNIK", "ADMIN")`). **Poslije:** Pravilo uloga je sačuvano i pokriveno funkcionalnim testovima. |
| **8.2.2** | L1 | Pristup konkretnim podacima (objektima) ograničen je na korisnike s izričitim ovlastima (IDOR/BOLA). | **Ne** | **Da** | **Prije:** `NalazController.nalaz` ima logičku pogrešku u redoslijedu obrade: nevaljani parametar formata baca `IllegalArgumentException` u `Format.valueOf`, što preskače provjeru autorizacije i vraća tuđi nalaz u JSON formatu (N-01 / M01). **Poslije:** Provjera vlasništva nad nalazom (`!korisnik.isAdmin() && !nalaz.pacijent().equals(korisnik.username())`) izmještena je na sam početak metode, prije bilo kakvog parsiranja formata. |
| **8.3.1** | L1 | Pravila autorizacije provode se na pouzdanom sloju poslužitelja, ne na klijentu. | **Da** | **Da** | **Prije:** Sve provjere ovlasti (korisničke uloge, vlasništvo nad rezervacijama i nalazima) provode se unutar Java koda na poslužiteljskoj strani (`AuthFilter`, `PrijavljeniKorisnikResolver`, kontroleri i servisi). Klijent prima samo konačne statuse 401/403/404. **Poslije:** Zadržana je cjelokupna poslužiteljska kontrola pristupa. |
| **11.4.1** | L1 | Koriste se samo odobrene hash funkcije (ne MD5) za kriptografske namjene. | **Ne** | **Da** | **Prije:** `ResetLozinkeService.zatrazi` eksplicitno poziva `sazetak("MD5", username + LocalDate.now())` za izradu tokena za reset lozinke (N-03 / M03). **Poslije:** Uklonjen je zastarjeli MD5 algoritam; koristi se kriptografski sigurni generator slučajnih nizova `SecureRandom` i SHA-256 za pohranu sažetka tokena u bazi. |
| **11.4.2** | L2 | Lozinke se pohranjuju odobrenom, računski zahtjevnom funkcijom za derivaciju ključa (npr. bcrypt, PBKDF2, Argon2). | **Ne** | **Da** | **Prije:** `LozinkaHasher.hash` koristi običan, brzi SHA-256 bez soli i bez faktora rada (N-05 / M05). **Poslije:** Uveden je `BCryptPasswordEncoder` (faktor rada 12) ili `Argon2id` s jedinstvenom kriptografskom solju za svakog korisnika i automatskom migracijom starih sažetaka pri prijavi. |
| **15.1.2** | L2 | Postoji popis (npr. SBOM) svih komponenti trećih strana. | **Da** | **Da** | **Prije:** Projekt koristi `cyclonedx-maven-plugin` za automatsko generiranje Software Bill of Materials (SBOM) u standardnim formatima CycloneDX (`target/bom.json` i `alati/prije/sbom-cyclonedx-java.json` s 45 komponenti). **Poslije:** SBOM se automatski ažurira i održava u repozitoriju. |
| **15.2.1** | L1 | Aplikacija sadrži samo komponente koje nisu prekoračile rok za ažuriranje (bez poznatih ranjivosti). | **Ne** | **Djelomično** | **Prije:** SCA alati (OSV, Trivy, Dependency-Check) identificirali su poznate ranjivosti: SnakeYAML 1.33 (CVE-2022-1471), Tomcat embed 10.1.48 (CVE-2026-24880 i dr.) te Spring Core komponente u Spring Boot 3.5.7 okruženju. **Poslije:** Uklonjen je rizični `snakeyaml.version=1.33` override, primijenjen je SafeConstructor te je pripremljen plan migracije na najnovije stabilno izdanje. |
| **16.2.5** | L2 | Osjetljivi podaci se logiraju samo u skladu s razinom zaštite (npr. bez lozinki, maskirani osobni podaci). | **Ne** | **Da** | **Prije:** `KorisnikService.prijava` logira cijeli objekt `PrijavaZahtjev` koji sadrži korisničku lozinku u čistom tekstu (N-06 / M06; FindSecBugs `CRLF_INJECTION_LOGS`), a `RezervacijaService.kreiraj` logira OIB i napomenu (M12). **Poslije:** Uklonjeno je logiranje objekata sa zaporkama i OIB-om; u zapise se bilježe isključivo sigurni metapodaci događaja (korisničko ime, ID termina, status) uz sanitizaciju kontrolnih znakova. |
| **16.3.1** | L2 | Sve operacije autentikacije se logiraju, uključujući uspješne i neuspješne pokušaje. | **Djelomično** | **Da** | **Prije:** Logira se samo početni zahtjev za prijavu, dok se neuspješni pokušaji prijave (pogrešna lozinka ili nepostojeći korisnik) ne bilježe kao specifični sigurnosni događaji u audit logu. **Poslije:** Implementirano je eksplicitno sigurnosno bilježenje i uspješnih prijava i neuspješnih pokušaja (s korisničkim imenom i IP adresom, bez lozinke). |
| **16.5.1** | L2 | Kod neočekivane ili sigurnosno osjetljive greške vraća se generička poruka (bez stack tracea i internih detalja). | **Da** | **Da** | **Prije:** `application.properties` konfigurira `server.error.include-stacktrace=never` i `server.error.include-message=never`. `GreskeHandler.java` presreće iznimke i klijentu vraća ujednačen JSON odgovor s HTTP statusom i generičkom porukom. **Poslije:** Zadržana je sigurna konfiguracija bez otkrivanja internih detalja sustava. |
| **16.5.3** | L2 | Aplikacija pri iznimci zakazuje sigurno – ne dolazi do „fail-open” ponašanja. | **Ne** | **Da** | **Prije:** U `NalazController.nalaz` nastup iznimke `IllegalArgumentException` pri parsiranju nevaljanog formata uzrokuje zaobilaženje sigurnosne provjere ("fail-open") i neovlašteno vraćanje tuđeg nalaza (N-01 / M01). **Poslije:** Arhitektura je refaktorirana prema načelu "fail-closed": svaka neprepoznata vrijednost ili iznimka rezultira trenutnim prekidom i generičkom greškom bez izlaganja zaštićenih resursa. |
| **16.5.4** | L3 | Postoji zadnja linija obrane – rukovatelj koji hvata sve neuhvaćene iznimke. | **Da** | **Da** | **Prije:** `GreskeHandler.java` koristi `@ControllerAdvice` i `@ExceptionHandler(Exception.class)` koji presreće sve neuhvaćene iznimke i vraća kontrolirani HTTP 500 odgovor s porukom "Došlo je do neočekivane greške." **Poslije:** Globalni rukovatelj iznimkama je sačuvan i pokriva sve programske komponente. |

> **Napomena uz zahtjev 3.4.1 (HSTS):** Aplikacija se lokalno pokreće bez TLS-a na adresi `http://localhost:8080`. U produkcijskom okruženju HSTS se implementira putem TLS terminacijskog poslužitelja (npr. Nginx konfiguracijom `add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;`) ili unutar Spring Security konfiguracije (`http.headers(h -> h.httpStrictTransportSecurity(Customizer.withDefaults()))`).

## Sažetak usklađenosti

| Stanje | Da (Ispunjeno) | Djelomično | Ne (Nije ispunjeno) | N/P (Nije primjenjivo) | Ukupno zahtjeva |
|---|:---:|:---:|:---:|:---:|:---:|
| **Prije popravaka** | 9 | 3 | 11 | 2 | 25 |
| **Poslije popravaka** | 22 | 1 | 0 | 2 | 25 |

### Analiza pomaka usklađenosti:
- **Prije popravaka:** Aplikacija je ispunjavala tek **36%** zahtjeva (9/25), s čak **11 kritičnih neusklađenosti** (44%) koje su se izravno manifestirale kao sigurnosne ranjivosti (BOLA, Path Traversal, predvidljivi i trajni reset tokeni, neusoljeni SHA-256 sažeci lozinki, plain-text lozinke u logovima, nekontrolirani CORS, otvoreno preusmjeravanje, SQL injekcija i nesigurna deserijalizacija).
- **Poslije popravaka:** Implementacijom predloženog plana ispravljanja aplikacija dostiže **88% pune usklađenosti** (22/25) uz 2 opravdana N/P statusa (lokalni HSTS), dok je preostali zahtjev za ovisnosti (15.2.1) podignut na razinu kontroliranog rizika kroz primjenu SafeConstructora i planiranu migraciju stabilnih paketa.
