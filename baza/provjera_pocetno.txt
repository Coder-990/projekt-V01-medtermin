Z2.2     PALO     Aplikacijska prijava nije u ulogama poslužitelja (sysadmin…) i nema CONTROL SERVER
                  -> ALTER SERVER ROLE sysadmin DROP MEMBER [medtermin_app]; – aplikaciji ne trebaju prava na razini poslužitelja.
Z2.3     PALO     Aplikacijski korisnik nije u fiksnim ulogama baze (db_owner, db_datareader…)
                  -> ALTER ROLE db_owner DROP MEMBER [medtermin_app]; prava dodijelite preko vlastite uloge (Z3).
Z2.4     PALO     Postoji vlastita administratorska prijava, a sa je onemogućen
                  -> CREATE LOGIN <ime> … CHECK_POLICY = ON; ALTER SERVER ROLE sysadmin ADD MEMBER <ime>; ALTER LOGIN sa DISABLE; pa upišite ADMIN_LOGIN/ADMIN_PASSWORD u .env i docker compose up -d.
Z2.5     PALO     Korisnik podrska nije u db_datareader niti drugim fiksnim ulogama
                  -> ALTER ROLE db_datareader DROP MEMBER podrska; (korisnika podrska nemojte brisati – treba za Z4).
Z3.1     PALO     Uloga uloga_aplikacija postoji, medtermin_app je član i aplikacija i dalje radi (SELECT/INSERT)
                  -> CREATE ROLE uloga_aplikacija; GRANT … ON dbo.<tablica> TO uloga_aplikacija; ALTER ROLE uloga_aplikacija ADD MEMBER [medtermin_app];
Z3.2     PALO     Aplikacijski korisnik ne može mijenjati shemu (CREATE/ALTER/DROP, ALTER ANY USER)
                  -> Aplikacija ne smije imati db_owner/db_ddladmin ni GRANT ALTER/CONTROL; DDL radi administrator (ili alat za migracije s posebnom prijavom).
Z3.3     PALO     Aplikacija ne može čitati ni mijenjati dnevnik dbo.revizija (puni ga samo okidač)
                  -> Ne dodjeljujte prava na dbo.revizija (po želji DENY SELECT, UPDATE, DELETE … TO uloga_aplikacija); okidač i dalje upisuje zbog ownership chaininga.
Z3.4     PALO     Uloga public nema prava na korisničke objekte i sheme
                  -> public = svi korisnici baze (i guest). Pronađeno: SELECT na shemi dbo. Koristite REVOKE … FROM public.
Z4.1     PALO     Na dbo.rezervacije postoji uključena sigurnosna politika s FILTER predikatom (RLS)
                  -> CREATE FUNCTION … WITH SCHEMABINDING; CREATE SECURITY POLICY … ADD FILTER PREDICATE …(pacijent) ON dbo.rezervacije WITH (STATE = ON);
Z4.2     PALO     RLS radi: aplikacija vidi samo zapise korisnika iz SESSION_CONTEXT(korisnik), ADMIN sve
                  -> Aplikacija kao ana vidi svojih 1 i tuđih 1 zapisa; bez konteksta 2; kao admin 2 vlasnika. Očekivano: ≥1, 0, 0, ≥2. Filtrirajte po pacijent = SESSION_CONTEXT(N'korisnik'); korisnici s ulogom ADMIN vide sve; bez konteksta aplikacija ne vidi ništa.
Z4.3     PALO     Stupci korisnici.oib i korisnici.email su maskirani (Dynamic Data Masking)

Z4.5     PALO     Podrška ne može čitati password_hash i nema UNMASK

Z5.2     PALO     TDE certifikat je sigurnosno kopiran s privatnim ključem u ./backup
